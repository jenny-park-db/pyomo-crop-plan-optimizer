# crop-plan-agent

The planning agent behind Crop Plan Studio's Agent tab (spec §7): LangGraph on the Agent Bricks runtime,
deployed as the Databricks App `agent-bricks-crop-plan-agent`. It answers what-ifs by running the solver,
data questions through Genie (with SQL), and robustness questions with stress tests.

## What is ours and what is the scaffold

Generated by `agentbricks init --framework langgraph --name crop-plan-agent --disable-chat-app
--memory-store crop-plan-agent-memory --session-store crop-plan-agent-sessions agent`
(databricks-agentbricks 0.7.0). Changed from the template:

| File | Change |
|---|---|
| `agent/agent.py` | system prompt, the Studio tools built per request, no approval gate |
| `agent/prompt.py`, `agent/studio.py`, `agent/crop_tools.py` | new: prompt, Crop Plan Studio client, tools |
| `agent/tools/` | sample tools deleted (tools that act as the user can't live here) |
| `agent.toml` | fixed tracing experiment name, `[auth.user]` with `sql` + `dashboards.genie` |
| `pyproject.toml` | `databricks-agentbricks` pinned to the CLI's minor version |
| `tests/test_agent.py` | sample-tool tests replaced; `tests/test_studio.py`, `test_crop_tools.py`, `test_prompt.py`, `test_eval_scorers.py` new |
| `evals/` | new: the evaluation set, scorers, and runner |
| `.gitignore` | `uv.lock` and the CLI's generated coding-agent docs are never committed |

`runtime/` and `agent/mcps.py` are the template's, unchanged. To see the full generated project (and its
`AGENTKIT_CONTRACT.md`), run the init command above in a scratch directory.

## How it acts

Every tool runs as the person chatting (`[auth.user] required = true`). `solve_scenario`, `stress_test_plan`,
and `get_stress_test` call Crop Plan Studio's `/api/studio/*` routes with that user's token, so the app's
validation, dedupe, and job start apply and Studio records the user; the agent itself writes no SQL and calls
no Jobs API. Genie is the CLI's `genie_agent` tool on the "Crop Plan Results" space, bound at deploy time.

## Develop, test, deploy, evaluate

```bash
uv sync && uv run pytest -q                                  # unit tests (CI runs these from public PyPI)
cd .. && uv run python scripts/deploy_agent.py --profile <profile>   # deploy + point Studio at it
cd agent && uv run python -m evals.run_eval --profile <profile>     # live evaluation (not in CI)
```

Never run `agentbricks deploy` from this directory: it writes workspace-specific settings into `app.yaml`.
`scripts/deploy_agent.py` deploys from a staged copy outside the repo (`<tmp>/pyomo-crop-plan-agent-deploy/`;
`databricks sync` would skip a copy under the gitignored `build/`).
